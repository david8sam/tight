# Windows installer preview

The Windows CI artifact includes `installer/TIGHT-<version>-windows-x64-preview-setup.exe` alongside the portable app folder. The installer contains Electron, the backend, and the browser assets. It does not download a runtime or require Node or Git on the player's PC.

1. Download `TIGHT-windows-x64-preview` from a successful Actions run and extract it.
2. Open the preview setup executable in its `installer` folder.
3. Complete setup, then open **TIGHT** from the Start menu.
4. Create a game and use **Wi-Fi sharing** to invite phones on the same private network.

This preview is unsigned. Windows may display a publisher or reputation warning. Use only the artifact from the intended repository and successful run. The preview is for evaluation and does not authorize public distribution of the bundled game material.

The installer targets Windows x64 and installs for the current user under `%LOCALAPPDATA%\Programs\TIGHT`. It requests no administrator elevation. Windows 11 x64 is the qualification target; clean standard-user machines remain to be tested in #26. ARM64 is not supported by this build.

Remove the app from **Settings > Apps > Installed apps**, or run **Uninstall TIGHT.exe** in its install folder. Uninstall removes the Start menu shortcut and application files. It preserves saved games in `%LOCALAPPDATA%\TIGHT` and the per-user Chromium profile. Reinstalling uses those existing games. Export important games before changing versions. Close TIGHT before installing or removing it; do not interrupt a live game to update. Setup and uninstall refuse while a TIGHT process is running. Interactive setup explains how to quit; silent setup returns exit code 2. Neither path stops the host or its connected guests. The conservative process-name check also detects portable TIGHT instances.

## Build and verify

Run `npm ci --legacy-peer-deps` on Windows, then `npm run installer:windows:preview`. The command builds the existing self-contained app, then runs electron-builder's NSIS target against that packaged directory. `scripts/windows-installer-config.mjs` owns the app identity, per-user install policy, and artifact names. The packager and installer share `org.alvinxiao.tight` and `TIGHT.exe`. The original blue T icon is generated by `node scripts/create-desktop-icon.mjs` and contains no third-party artwork.

Windows CI runs the actual preview installer silently. It checks the Start menu target, per-user uninstall registration, application license and third-party notices, then launches the installed app to create a save in the default data directory. While the installed host and a paired guest are connected, CI runs both silent setup and silent uninstall and requires refusal with the original window, guest socket, and every installed file unchanged. The NSIS uninstaller launcher self-copies and returns before its child; the check waits for the complete process tree and verifies the outcome rather than treating that launcher’s exit 0 as uninstall success. After closing the host, CI runs an in-place installation, then an uninstall/reinstall. Each launch compares the complete game, name/archive/timestamp, and persisted device permission before a final uninstall. The runner must have no existing TIGHT installation or saved games. This check does not replace clean standard-user, SmartScreen, or physical phone testing.

The package retains Electron's `LICENSE`, Chromium's `LICENSES.chromium.html`, the repository's original MIT notice as `TIGHT-LICENSE.txt`, and `THIRD-PARTY-NOTICES.txt`. These notices are also available for review in the portable directory. Dependency notices do not resolve the separate rights to redistribute Twilight Imperium names, rules text, or artwork.

## Signed releases

`npm run installer:windows:release` is separate from preview packaging. It fails before building the installer unless the release environment supplies all of these values:

- `CSC_LINK` is the absolute path of the publisher's PFX certificate mounted by the release secret store.
- `CSC_KEY_PASSWORD` supplies its password through the release secret store.
- `TIGHT_RIGHTS_REVIEW_URL` points to the completed distribution-rights review over HTTPS.

A URL is a recorded review reference, not an automated legal decision. The release operator must check that review and the publisher credentials. Release mode rejects competing `WIN_CSC_LINK`, `WIN_CSC_KEY_PASSWORD`, and `CSC_NAME` aliases so the app and installer use the same supplied identity. Never commit certificates, passwords, or fabricated review approvals. The packager signs the app binaries, then electron-builder signs the installer and uninstaller. Mandatory signature checks reject a release when signing fails or the app and installer have different publisher certificates; signing alone does not guarantee Windows will suppress reputation prompts. Preview packaging rejects supplied signing credentials and explicitly disables executable signing.

No signing secrets, completed rights review, public release workflow, or automatic updater are supplied by this change. #23 remains open for signed distribution and installer qualification. #24 remains open for signed cross-version upgrade behavior, failed-update recovery, and offline qualification. The installer checks cover same-build in-place replacement and reinstall; they do not establish rollback to an older application after a schema migration. Builds never publish artifacts automatically; CI uploads only the unsigned evaluation artifact.

Installer builds require PowerShell 7 (`pwsh.exe`). The CI annotation wrapper uses the same shell as the Windows workflow, so its security cmdlets load from the matching PowerShell runtime. End users do not need PowerShell 7, Node, or Git.

## Manual beta update

1. Finish or pause the game and export important saves. Keep the existing installer and the complete TIGHT data folder as a separate backup before changing versions.
2. Quit TIGHT. Guests disconnect when hosting ends. Setup will not close a running host for you.
3. For a signed release, verify the publisher and use the installer from the intended successful release. Preview artifacts are explicitly unsigned evaluation builds.
4. Run setup for the same Windows account. An in-place installation preserves saved games and paired-device grants.
5. Open TIGHT and confirm the saved-game list before enabling Wi-Fi sharing again.

TIGHT has no automatic download or background install path. An incomplete download therefore cannot replace the working app. Database startup validates saves and creates a pre-migration backup; failed migration preserves the original database. A failed app installation may need the intended installer run again. Do not assume an older app can read a newer database. Restore a compatible pre-migration backup in a separate data folder when downgrading; automatic application rollback is not provided.

Use the [Windows and phone qualification procedure](windows-phone-qualification.md) to record exact installer identity, native prompts, physical-device results, and update or recovery failures. Its blank record does not establish a release pass.
