# Accessibility checks and remaining qualification

The browser suite includes a keyboard journey from creating a game through assigning a faction, color, and player, taking a strategy card, changing phases, and scoring an objective. It also checks focus restoration after closing a dialog and recovery from an unknown route. The host/phone journey locates setup selects by their accessible names.

An axe scan checks WCAG 2 A/AA and WCAG 2.1 AA rules on the home screen, new-game dialog, faction setup, strategy phase, action phase, and expanded scoring controls, including dark-theme and phone-width scoring. These are regression checks for the rendered states, not a claim of complete accessibility compliance. Failures retain the affected screen, rule, and node information in the test attachment and CI output.

Selects use stable IDs to associate labels with their controls. Full-screen dialogs have accessible names and support Escape. Buttons that change a game and buttons that expand details are separate controls; objective detail buttons no longer sit inside checkbox labels. Color choices retain text labels. Both themes select text colors using a 4.5:1 contrast threshold. The theme button names the theme it will switch to.

The planet modifier editor gives each numeric field and increase/decrease button a name that includes its resource or technology type. Its trait selector uses an ID without spaces so its visible label remains associated with the control. The DMZ checkbox reflects the selected saved modifier and Reset clears the override instead of leaving an uncontrolled switch in its old state. The planet-editor journey checks keyboard reset/save, committed values after reload, focus restoration, a narrow viewport, and axe scans in both themes.

Saved-game refreshes retain the loaded cards until the replacement list arrives. The rename dialog can therefore return keyboard focus to its original button after a successful save. A delayed-refresh journey checks the opener remains mounted, Save and Escape restore focus, and library actions stay disabled while manual refresh is pending.

The library action owner also restores focus after a temporarily disabled control becomes available. If archive or delete removes that control, focus moves to the Saved games heading, which is programmatically focusable without adding a Tab stop. Restoration waits until a closing dialog is removed and preserves focus that the user moved to another control while waiting. Delayed-response journeys cover refresh, archive, deletion, and that deliberate focus change.

The rename text field stays focused and becomes read-only while saving. Save and Cancel remain disabled during the request. If saving fails after submission from the Save button, focus returns to the name field when the disabled button left focus on the modal container or body. Focus held by another control is preserved. The name becomes editable so keyboard users can correct it and retry. Delayed storage-error journeys cover submission from both the text field and Save button. They verify pending edits and repeated Enter do not send duplicate writes, then reads the corrected name from the host after a successful retry.

Create, join, restart, and invitation requests share focus recovery for submit controls that remain mounted. After a request settles, focus returns to the submit control only when disabling it left focus on the modal container or body. Focus held by another control is preserved. When a completed request removes its submit control, device-access revocation falls back to Close and a missing-game rejoin falls back to Game Code. Rejoin also names the unavailable game in an alert. Both fallbacks preserve focus deliberately moved to another control. Cancellation clears the saved focus target. Join and rejoin buttons retain their accessible names while their pending indicators appear. Delayed-error journeys cover each dialog and deliberate focus changes.

Canceling device disconnection with Keep devices connected returns focus to Disconnect paired devices after the confirmation controls disappear. Enter and Space journeys check repeated cancellation, navigation to Close, focus restoration to Pair a device, and successful use of an invitation that cancellation must leave valid.

Connected-device Refresh and Retry stay focusable while loading, with unavailable and busy states exposed to assistive technology. Their activation handler ignores input until the read completes. Keyboard journeys cover successful and failed refreshes, repeated Enter and Space during a pending read, focus deliberately moved to Close, retry, and polling cleanup when the panel collapses.

Wi-Fi Start and Stop retain keyboard focus while a native change is pending and expose busy and unavailable states. Their handlers reject repeated activation. Close stays focusable but cannot close the dialog until the change settles. A failed change leaves focus available for retry; a successful Stop moves focus to Close when it removes the activating button. Focus deliberately moved to another control is preserved. Browser tests control the native bridge to cover rejection, keyboard retry, success, and duplicate Enter/Space. Native integration tests still exercise the real sharing transport; these focus tests do not qualify physical network changes.

Before release, issue #17 still requires assistive-technology and manual keyboard qualification of the remaining dialogs, planet editing, multiple simultaneous faction editors, reference pages, and phone clients. Check both themes, 200% and 400% zoom, visible focus, contrast and non-color state cues, error announcements, touch targets, and focus after destructive actions. Automated scans cannot establish those results by themselves.

The player-name join dialog keeps Continue focusable and named while awaiting confirmation. It exposes busy and unavailable states, rejects repeated activation, and locks the submitted name and player selection until confirmation or the existing timeout. Delayed real-host snapshot journeys check pending edits, timeout focus, deliberate focus on Close, and late confirmation of the original identity across reload.

Player selection tracks new-name entry separately from an existing identity. Choosing Create New Player starts with an empty, controlled name field and keeps Continue disabled until a valid name is entered. A saved player named Create New Player remains a distinct, selectable identity. Keyboard journeys cover both choices, switching modes, visible draft values, durable player names, and reload.

The expanded faction reference labels its read-only Commodities field. Browser regressions open the reference with keyboard activation, check its named value, and scan the expanded page at phone width in both themes. These rendered-state scans do not replace reference-page assistive-technology qualification.

Faction-reference bulk controls track the section indices, excluding TypeScript enum reverse-map names. Keyboard regressions expand every section individually and collapse them individually after Expand, then verify the opposite bulk action still works.

Faction-reference Next and Previous navigation recover focus on the same directional control after loading. A failed read focuses Retry loading information, then returns to the directional control when retry succeeds. Recovery preserves focus deliberately moved elsewhere. Browser journeys hold real faction reads to check success, failure and retry, and deliberate focus changes in both directions.

Faction-reference selection and Randomize also retain their control identity while the toolbar is replaced by loading feedback. Success restores the initiating control when focus was lost to the document. Failure focuses Retry, then a successful retry returns to the initiating control. Deliberate focus elsewhere is preserved. Browser journeys exercise both controls with held real reads, successful and failed responses, and retry.

When the initial faction-reference read fails before any control is selected, keyboard activation of Retry records the faction selector as its recovery target. A successful retry focuses that selector; another failure focuses Retry again. Existing navigation or Randomize targets take precedence, and focus deliberately moved elsewhere is preserved. Browser journeys verify initial success, repeated failure and retry, and deliberate focus changes.

The game-code Join dialog uses native form submission. Enter from Game Code and activating Join share the same validation and request owner. The disabled submit button blocks incomplete codes; a pending request rejects repeated submission. Browser journeys cover lowercase normalization, held real validation responses, a failed read followed by Enter retry, and button activation. This does not grant access to an unpaired phone; invitation and backend permission checks still apply.

The saved library offers named Search saved games and Sort saved games controls. Search combines name/code matching with archive visibility, and Clear search returns focus to the search field. Empty search results are distinguished from an empty or fully archived library. When a successful rename removes the last matching card, focus falls back to the Saved games heading after the dialog closes. Browser journeys cover filtering, sorting, refresh, rename recovery, and phone-width axe checks in both themes.
